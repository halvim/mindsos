### Hotfix ledger (issues surfaced during tester run; fixed in same chat)

#### B-06-T1 — `Dockerfile` + `tests/_shared/sentinel_paths.py` missed `mindsos_instances/`

Surfaced on first in-container pytest run: collection errored 41 times
with `ModuleNotFoundError: No module named 'mindsos_instances'`. The
Dockerfile (both `prod` + `test` stages) has explicit
`COPY mindsos_cli ./mindsos_cli` + `COPY mindsos_core ./mindsos_core`
directives; the new top-level package was never added. Fix: added
`COPY mindsos_instances ./mindsos_instances` to both stages. Sentinel
list at `tests/_shared/sentinel_paths.py` extended with 11 new Phase 06
sentinel paths (the new package's files + `mindsos_core/_observers.py`
+ `mindsos_cli/commands/instances.py`). First top-level package
addition since Phase 02 — the round-7 P62 A package-integration
checklist anticipated this footgun.

#### B-06-T2 — CLI subprocess test fixture used wrong flag names

Surfaced after B-06-T1 cleared collection: 11 of 12 Phase 06 CLI tests
errored with `Usage: mindsos graph create [OPTIONS]`. The fixture
`populated_mg` in `tests/phase_06/test_cli_instances.py` assumed
fictional flag names (`--metagraph` on `graph create`, `--type-name`,
`--source-id` / `--target-id`, `--value` as a flag). Real Phase 03/05a
signatures: `graph create --name N --role R` (NO `--metagraph` —
metagraph attachment is a separate `metagraph add-graph` step);
`graph add-node <value> --name N --type T --json` (value is positional,
`--type` not `--type-name`); `graph add-edge --name N --source ID
--target ID --type T --json` (NO `-id` suffix on endpoint flags).
Additionally, mutations on metagraph-owned graphs are REFUSED by
`_refuse_if_metagraph_owned` (Q4-B), so the fixture had to be reordered:
**build the graph standalone first, THEN attach to the metagraph**.
Fix: rewrote `populated_mg` with correct signatures + the standalone-
first ordering.

#### B-06-T3 — Unknown `--metagraph` exited 1 instead of 2

Surfaced after B-06-T2 cleared the fixture errors:
`test_instantiate_node_unknown_metagraph_exits_2` asserted `1 == 2`.
Phase 06 row §H (round-7 P53 A) maps "resource-not-found" → exit code 2.
The underlying `_load_or_die` in `mindsos_cli.commands.metagraph` raises
`typer.Exit(code=1)` on `FileNotFoundError` (Phase 05a convention; can
be exit 1 *or* exit 2 depending on the calling subapp's
resource-not-found policy). Phase 05d's `metagraph-schema validate` had
the same problem and used the P41 A exit-code split (0/1/2/3) at the
caller side. Fix: wrapped `_load_or_die` in
`mindsos_cli/commands/instances.py` to convert exit code 1 →
`EXIT_NOT_FOUND` (=2) for all `instances` verbs. Phase 05's other
subapps unaffected.

### Implementation pushback during round-7 (filed in PHASE_06_IMPLEMENTATION_LOG.md §3)

#### P66 — Late-added graphs needed observer subscription

Surfaced during Phase 06 library-test run (9 of 90
`tests/phase_06/test_cascade_observer.py` cases failed): cascade did not
fire when `Metagraph.add_graph(g)` happened AFTER
`attach_registry(mg)`. Root cause: `ElementRegistry.__init__` subscribes
to `metagraph.graphs.values()` snapshot at attach time only. Fix: added
`Metagraph._graph_added_observers` plumbing + new
`register_graph_added_observer(cb)` method; `Metagraph.add_graph` fires
every registered callback after the unification step;
`ElementRegistry.__init__` subscribes via the new hook. ~15 LOC in
Core + ~3 in registry. Mirror of the existing `_remove_observers`
pattern. Documented in PHASE_06_IMPLEMENTATION_LOG.md §3.
