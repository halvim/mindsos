### Step 0 probe outcomes (P68 A + P97 B; 2026-05-13)

- **P68 A + P89 A — CREATE INDEX syntax**: FalkorDB v4.18.3 REJECTS
  `CREATE INDEX IF NOT EXISTS` as a hard Cypher-parser syntax error
  (not an "already exists" runtime error). Bare
  `CREATE INDEX FOR (n:L) ON (n.id)` and
  `CREATE INDEX FOR ()-[r:RT]-() ON (r.id)` both work. Re-creating
  returns `Attribute 'id' is already indexed` — substrings `already`
  + `indexed` both match the defensive try/except in
  `bootstrap.py:bootstrap()`. Resolved via hotfix B-07-T1.

- **P97 B — _props_json oversized write**: FalkorDB v4.18.3 accepted
  a 10 MB string property write without complaint. P83 C "no cap"
  architectural decision validated; the narrow chained driver-
  exception catch in `metagraph_repository.py:_safe_run` stays as a
  future-proof guard (zero cost when no exception fires).
